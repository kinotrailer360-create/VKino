# VKino Studio 0.3 — кнопка ПК-монтажа (черновая ветка)

## Что добавлено

1. В приватном Telegram-чате администратора команда `/studio_pc` и кнопка «🖥 Монтаж на ПК» после `/studio`.
2. Бот показывает несколько **завершённых** проектов из существующего Studio, в которых уже утверждены **все** MP4-блоки. Кнопка создаёт в отдельной очереди Windows задачу `assemble_clips`.
3. Windows-агент получает список файлов только с owner-scoped `fileId`, проверяет SHA-256 и длину, соединяет их **без изменения видеоряда и озвучки**.
4. Результат возвращается по частям на VPS как `awaiting_review`; бот сообщает, что черновик готов. До 45 МБ можно получить черновик в личный чат через кнопку.
5. Ни одна операция не вызывает YouTube API или публикацию. Авторское финальное согласование остаётся обязательным.

## Важное ограничение

Это **проверка полного маршрута Telegram → VPS → Windows → Telegram** на уже утверждённых сценах. Сборка отдельных сцен (поиск медиа, TTS, субтитры) пока выполняется существующим VKino. Перенос тяжёлого *покадрового* рендера на Windows — следующий этап, он **не реализован** в версии 0.3.

На первом этапе задача под ПК создаётся из **завершённого** Studio-задания `assemble`. Если в базе нет такого задания или его видео удалено из Studio через семь дней, кнопка объяснит причину. Ранее одобренная версия считается отдельным историческим проектом; после изменений на сайте нужно снова утвердить и собрать все сцены.

## Безопасность и совместимость

- Все команды и кнопки доступны только администраторам VKino в приватном Telegram-чате; запросы к базе привязаны к `admin_id`.
- Windows-агент подключается только исходящим HTTPS, не принимает команды оболочки, ограничивает файлы локальной папкой `media`, сверяет хеши и использует lease-токен.
- Размер входного файла на VPS по-прежнему не более 50 МБ; итог не более 256 МБ. Telegram-черновик отправляется лишь при размере до 45 МБ.
- Сборка `assemble_clips` требует одинаковых форматов H.264 + AAC, разрешения 720x1280, FPS и аудиопараметров каждого клипа. Несовместимые клипы **не** склеиваются молча.
- Статус прав по умолчанию `unconfirmed`; происхождение трейлеров и права необходимо проверить автору.
- Существующие `studio_jobs`, `studio_worker_jobs` и миграции не изменяются. Новая миграция не требуется.
- Не сливать черновой PR в `main` и не разворачивать на VPS до проверки на тестовом окружении.

## Проверка

```bash
python -m pytest -q tests/test_vkino_studio.py tests/test_remote_worker.py tests/test_studio_pc.py
python -m py_compile bot.py shorts/studio_pc.py shorts/studio_pc_handlers.py shorts/studio_worker.py vkino_studio/remote.py vkino_studio/assembly.py
```

Синтетические тесты создают два H.264/AAC MP4 с FFmpeg, имитируют получение задания и проверяют отсутствие автопубликации. Они **не заменяют** интеграционный тест с PostgreSQL, реально включённым Windows-агентом и сервером.

## Ручной приёмочный сценарий (после staging-развёртывания)

1. Подключить Windows-агент по одноразовому коду `/studio` и запустить `python -m vkino_studio.remote --server https://ДОМЕН`.
2. На сайте Studio утверждать каждый исходник и каждый блок; выполнить текущую сборку на сайте.
3. В личном чате VKino отправить `/studio_pc` и выбрать завершённый проект.
4. Дождаться результата агента; проверить статус в `/studio_pc`.
5. Получить черновик, проверить соответствие кадров, озвучки и права. **Никаких публикаций до отдельного согласования.**
6. Проверить выключенный ПК, повторное нажатие (idempotency), неверный владелец, отозванный токен и файлы старше семи дней.

Windows 10 должен получать расширенные обновления безопасности или быть заменён на поддерживаемую систему. Входящие порты домашнего роутера открывать не нужно.
